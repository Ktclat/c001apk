# Flutter Markdown detail candidate

Integration candidate based on published main `2aa5348790778c229f8fed647d2b92aae1143d74`, preserving the Flutter 3.47.7 / Dart 3.13.5 toolchain and profile UI changes. The earlier source-only candidate was `6a85e5f4f8a916b7e07e9d331c88d57d11ed4823`. No merge, release, independent-review pass or device acceptance is implied.

## Reference and dependencies

Behavior reference: TG-Twilight/c001apk `98526cc30cc6ed5d96fc4bed32ee03dfc92b7024` (Markdown detail and overflow behavior). This does not import export, announcements, external-intent changes, arbitrary remote images or automatic device registration.

`markdown` is pinned at **7.3.1**, whose published SDK floor is Dart 3.9. Its official pub.dev archive SHA256 is `ee85086ad7698b42522c6ad42fe195f1b9898e4d974a1af4576c1a3a176cada9`. `characters` is pinned at **1.4.1**, already the target Flutter SDK's resolved transitive version, and is made explicit for raw-source grapheme paging. The integrated lockfile adds only markdown 7.3.1 and changes characters from transitive to direct without changing its version. No other dependency or toolchain version changes. HtmlWidget uses only existing core APIs compatible with the migration's **0.15.2**; no broader dependency upgrade is required.

## Covered behavior

- Detail-only Markdown: headings, emphasis/strong/strikethrough, inline/fenced/indented code, quotes, ordered/bullet/nested lists, rules, read-only `[x]` / `[ ]` task markers and safe explicit/reference links. Ordinary topic names, underscore names and single plain list items do not opt in.
- Applicable overflow menu matches upstream exactly: `查看原文` / `格式化显示`. Formatted is the default on entry. Raw and formatted scroll offsets are kept separately in the mounted detail, never in global storage.
- Ordinary raw text is the exact accepted API `message`. Structured raw aligns with native: separately labeled exact original title, cover address and `message_raw_output` JSON, never decoded/re-encoded/flattened. Missing fields are explicitly labeled. Raw source is inert text without live image/share cards. This deliberately improves on upstream’s per-text-block source switch. CR/LF, tags, entities, comments and Unicode are preserved. Formatted structured title/cover/image/share blocks retain their existing order and behavior. Titles use bounded legacy HTML; share labels and image descriptions keep literal Text characters/styles rather than interpreting entities, Markdown or emoji.
- Reading presets, Chinese locale, app font family/fallback, font scale and normal body weights apply to both raw and formatted text. Only code uses monospace, with the selected Chinese body font retained as fenced-code fallback. Comments, chats, feed previews and forwarded-feed previews are unchanged.
- Supported legacy HTML keeps paragraph/link/inline structure, local emoji decoration and vetted pre-existing HTTP(S) images. Entity-encoded tags stay text after one decode; emoji expansion touches only text nodes. Mixed supported HTML is not flattened into Markdown; existing newline and simple-bold display conventions are retained, but broader embedded Markdown is not newly interpreted. Unsupported tags/comments use full exact-source fallback with a visible notice. No HTML script, inline CSS, event attribute or unsafe image scheme executes. Legacy remote image capability is preserved, not introduced for Markdown.
- New Markdown and mixed Markdown/HTML images are readable inert `图片未加载` placeholders, including official-looking HTTPS URLs. No added image HTTP/DNS/redirect/decode calls. Existing separate structured images are not broadened or reimplemented.
- Links are validated before the existing app router. JavaScript/data/file/protocol-relative/credential/control/malformed-escape destinations are inert. Angle-bracket HTTP(S) autolinks are supported by the pinned core parser; email links remain inert. Heading anchors and arbitrary URI schemes are deferred.

## Ownership and bounds

Accepted-response snapshots are immutable, scoped to account, account generation, feed ID and exact body bytes (Dart UTF-16 strings). There is no static source/parser/result cache. Equal-body metadata refresh retains the display mode; a new body/owner resets it. Account replacement clears detail and comments without automatic reload; stale network/parser completions cannot publish. Checks also cover the pre-notifier account-persistence gap, retained overflow/FAB/Markdown and legacy link callbacks, structured body actions and queued raw-page scrolling. Owner-scoped likes suppress interceptor-level toasts so stale failures cannot leak into the replacement body.

Parsing and source pagination use a detail-owned disposable isolate with an actual 2-second kill timer, cancellation on replacement/dispose and stale-result identity checks. An aggregate detail is limited to 128 text fields / 262,144 UTF-16 units for formatting; exceeding it selects source fallback rather than dropping fields.

Before the Markdown library runs, a linear preflight bounds each source to 65,536 UTF-16 units, 1,024 lines, 8,192 units per line, 16,384 per continuous paragraph, 4,096 total syntax delimiters, 128 per line and 64 per continuous paragraph, 16 bracket/container levels, 48 leading indentation columns and 512 consecutive ASCII alphanumeric units. The token cap bounds the pinned inline parser’s repeated suffix-regex scans. Blank lines reset only paragraph budgets; soft lines/CRLF cannot evade recursion limits. Table delimiters and footnote syntax select exact-source fallback before extension processing. `TableSyntax`/footnotes/InlineHtml are not registered.

The tagged library contains recursive blockquote/list parsing, `Document._parseInlineContent` and `InlineParser._combineAdjacentText` before a caller can inspect its AST. Preflight therefore precedes the 2,048-node / 24-depth AST and sanitized-DOM checks. Generated HTML is capped at 131,072 UTF-16 units before the final eager-widget gate. After sanitizer/newline/local-emoji expansion, that separate layout gate caps HTML at 16,000 units, total text at 4,000 units, any text block/inline run/code at 2,000 units, DOM nodes at 128, depth at 12 and images at 24. It is rechecked at the rendering boundary; overflow retains exact paginated source with a visible notice. Entity-decoded root text is preflighted again before mixed-markup classification. Raw text is paginated off-main with a hard 4,000 UTF-16-unit page bound and is never reparsed as HTML. Normal boundaries preserve complete graphemes. A single pathological overlong grapheme is explicitly labeled and split at code-point boundaries without dropping or modifying any source. Indexed iteration and a remembered split boundary avoid repeated suffix copying and scanning. Raw page indexes and each mode’s scroll offsets stay in the exact controller/body scope, including lazy article disposal. Raw paging actions are bound to the exact page, request generation, index and position object: double clicks and retained Next/Previous/retry callbacks cannot skip or duplicate segments. Flutter paginates each labeled raw field separately; native uses one source-ordered page index across fields. Both preserve exact original fields and inert display.

## Deferred or deliberately different

- Task state uses deterministic ASCII `[x]` / `[ ]` rather than checkbox glyphs: bundled Noto CJK lacks U+2610/U+2611, and no OS symbol fallback is assumed. This is an intentional appearance difference from native checkbox markers.
- Tables, footnotes, arbitrary HTML, math/Mermaid, syntax highlighting and rich Markdown images. Unsupported recognized structures retain source with a notice, not partial fake formatting.
- Coolapk native HTML-link normalization mixed with Markdown, custom emoji decoration inside formatted Markdown, preview conversion, heading anchors and bare-URL autolinks.
- Export, announcements, intents, responsive layouts, startup identity and new network behavior remain later increments.
- Raw full-document selection and raw paging restoration across leaving/re-entering detail are not provided; toggling formats within the same body does retain the raw page. Existing long-press source copy remains separate.
