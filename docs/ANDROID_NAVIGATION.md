# Android 悬浮 Tab 导航

本分支提供一个可选的**悬浮底部 Tab 栏**，保持已有导航信息架构。

## 使用

在 **我的 → 设置 → 外观与导航 → 悬浮 Tab 导航** 打开开关。字体、字号和正文排版在独立的 **阅读与字体** 分类中设置，默认使用内置思源黑体和舒适阅读。
启用后，主页／关注／我的三个底部入口显示为紧凑的居中胶囊（默认 268×62dp，选中图标与文字同行），而不是把完整的 Material NavigationBar 塞进大圆角背景中。关闭即恢复传统底栏。
默认关闭，已有用户不会在升级后突然改变操作方式。该设置持久保存在 Hive 的 `floatingTabBar` 字段。

启用悬浮导航后，可设置 **滚动时隐藏悬浮导航**（默认开启）：向后浏览内容时，导航随滚动平滑向下移出并淡出；反向滚动时恢复。关闭此选项会立即恢复导航，并在继续浏览时保持显示。该偏好独立保存为 `hideFloatingTabBarOnScroll`，退出设置、重启或切换导航样式后仍然保留；旧版的 `floatingNavigationPolicy` 不影响新开关。

- **手机竖屏**：导航位于页面底部居中，宽 268dp、高 62dp，选中项水平显示图标与标签，另外两项只显示图标（长按提示完整名称）。滚动显隐由上述开关控制。列表底部仍保留足够滚动距离，确保最后一条可完整阅读；发布动态和更新按钮主动避让。
- **输入键盘时**：隐藏底部导航（悬浮版与经典版），为评论、搜索或私信输入留出空间；收起键盘自动恢复。
- **横屏与宽度 ≥600dp 的大屏设备**：悬浮模式继续使用紧凑底部导航；关闭悬浮模式后采用 `NavigationRail`。
- **中尺寸屏幕**：浮动栏固定约 268dp 居中，最低 48dp 的触控命中区域；文字放大时可增长至 66/72dp，并以语义标签保留所有导航名称。
- **首页顶部的“应用、动态、热门”等标签**：不受影响。
- **重复点击主页／关注入口的返回顶部动作**：沿用原来的控制器，不改变事件逻辑。
- **账号切换**：仍然清理旧账号页面和路由；仅改变导航容器，不另建账号状态。
- **字体放大**：根据系统字号缩放适当增加导航栏高度，避免标签受挤压。

它是 Flutter 应用内部的页面组件，**不会在其他应用上层显示，也不需要 Android 悬浮窗权限**。不开启新权限、不读取个人数据，也不增加网络请求。

## 实现

- `lib/components/floating_tab_bar.dart`：独立的三项紧凑导航控件，真实命中区域不小于 48dp，选中项以水平图标/文字突出；语义标签及 Tooltip 覆盖所有入口。**不再嵌入标准 NavigationBar**，避免系统 SafeArea 和固有高度叠加造成截图中巨大胶囊。
- `lib/pages/main/main_page.dart`：监听 Hive 的导航样式与滚动隐藏开关，即时切换并保留 PageView 的控制器及选中页。更改滚动隐藏选项时恢复导航并清除旧的滚动意图，避免旧手势的惯性滚动立即再次隐藏导航。
- `lib/pages/settings/settings_page.dart`：开关入口。

## 自动化检查

- 开关默认值、持久化与独立性。
- 竖屏动态启用／关闭，切换主页、关注、我的时选中状态正确。
- 旋转与大屏切换保留所选导航样式，经典导航在宽屏使用侧栏。
- Root PageView 保持全高；消息页、动态列表、应用列表、话题列表和首页卡片的滚动范围提供额外底部间距，悬浮栏下方内容可以滚动至可读区域。
- FAB 避开胶囊导航，避免“发布动态”与“更新应用”操作按钮重叠。
- 无论滚动隐藏开关是否开启，输入法弹出时底部导航仍自动隐藏、恢复。
- Flutter 带真实思源黑体的合成视觉预览图 `build/review/floating-tab.png`。
- 用户之前的字体、账号、离线回归测试全部必须继续通过。

自动化仅代表代码行为正常；实际设备仍需复查不同 Android 系统手势条、三键导航、折叠屏、横屏和无障碍大字号。悬浮栏只占用必要的命中区域，不会申请系统悬浮窗权限。


## 严格审阅阶段：外部模型验收关卡

针对 1178×2537 真机截图中旧版巨大底栏的明显问题，本轮使用**固定几何尺寸验收**：测试手机 390×850dp、底部系统手势安全区 24dp，确保导航实际宽 268dp、高 62dp，底边在系统导航区域以上、3 个点击区均 ≥48dp。另用 320×780dp / 2 倍系统字体缩放复查高度 ≤72dp、完整可点击、切换选中项正确。

滚动显隐状态由独立 `ValueNotifier` 驱动，只重建悬浮导航的动画，不因滚动反复重建承载图片的 `PageView`。键盘、横屏与平板、账号切换，以及本地数据/字体设置回归仍需要 CI 成功。

**外部模型审核属于单独关卡**：在独立审核结果出来之前，不宣称最终视觉和交互通过；自动化绿灯只说明已验证的场景符合断言。
